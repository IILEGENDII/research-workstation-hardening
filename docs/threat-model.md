# Trust and privacy

The auditor addresses false assurance from incomplete, stale, mis-scoped or misinterpreted configuration evidence. It assumes a trusted interpreter, kernel, clock, owner and system installation. A subject is an operator-chosen label. No machine identifier or hardware attestation binds that label to a computer.

The only live verb is collect. The two authorization flags record operator intent. The auditor cannot determine whether the operator owns a machine. Owner-selected local files receive the operator_selected_local_file assurance only after the operator explicitly selects --trust-local-file and the file claims local capture. Editable claims can be forged. Fixture and import evidence cannot satisfy workstation policies on the strength of their declared collection method alone. Keep original policy and snapshot bytes and a separately trusted record of their hashes if their integrity matters.

Published reports expose the selected checks, their values, volume letter if selected, label and times. Keep actual reports private. The program stores a small allowlist of native fields. It omits native error text, network information, raw identifiers, private paths and recovery material. The CLI's directory argument is visible to the local process environment while running. A compromised host can fabricate all observations.
